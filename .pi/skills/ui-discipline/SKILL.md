# ui-discipline — 视觉活的三条禁令

## 1. 配色禁区

产品基调：**中性黑白灰 + 磨砂玻璃，sage 绿是唯一强调色**（globals.css 注释原话："carried by content and state, never by chrome"）。禁止引入蓝紫、橙黄、屎黄、高饱和彩色——内容图片自带的除外。新 UI 必须复用既有 token/面板体系（PaneShell、settings 原语、mono-eyebrow），禁止自建新样式新配色。皮肤可以改形（字体/材质/边缘），**永远不许改色**（纸底/墨阶/强调色 = 主题 = 禁区）。

## 2. 假进度与撒谎控件禁令

- 进度显示用**真实进度**，前端等待必须与后端真实完成时间一致。后台 40 秒完成、画布还在转 = 高优 bug。
- **撒谎控件比死控件更坏**：只改自己标签/样式而不驱动真实数据的桩控件是禁区——死控件一眼看穿，撒谎控件骗过检查还骗过人。
- 面板上任何计数/清单，必须按当前实体**真正拥有、真正能用**的范围过滤后再显示，禁止把全局/共享数据源的扫描结果直接当自己的。进度别骗，数量也别骗。

## 3. 参考材料必须真看完

图/视频/文章/链接：**真打开、真看完**再答——禁止凭标题猜论点、拿摘要代原文、从结果反推。视觉参考先逐条提炼设计语言（排版/间距/圆角/材质）再动手；说不出细节就不算"已分析"。视频要说得出关键帧在第几秒发生了什么。每版改动要说明相对上一版改了什么，禁止无进展的重复生成和质量倒退。
