# self-paced-loop — 自己定节奏地反复做一件事

移植自 Claude Code 的 `/loop` 动态模式。**不是每轮都要人推一把,也不是无脑空转**。

## 三个零件她都已经有

| 要做的事 | 用哪个 |
|---|---|
| 等一个条件成立(端口起了/文件出现/CI 变绿) | 把"等"本身派成后台任务:`bash -c "until <条件>; do sleep 15; done"` + `timeoutMinutes` 兜底(见 coding-dispatch 的监视配方)。条件成立→完工唤醒叫她;等不到→超时也叫她 |
| 定时再看一眼 | `her_schedule_wakeup`(一次性闹钟;到点由 tick 拉起属主会话)——**醒来那一轮再约下一个,就是循环** |
| 记录这一轮干了什么 | 任务卡 / BACKLOG / 记忆,按事情的分量选 |

## 定节奏的规矩(照抄我的)

1. **别为了盯自己的后台任务而定闹钟**——后台任务完工会自己叫她。给那种情况定钟只有一个用途:**兜底**(万一它挂死了永远不叫),所以间隔要长(20 分钟以上)。
2. **盯外部状态**(CI、部署、别人的进程)才按状态真实变化的速度定:一个跑八分钟的 CI,定一次八分钟的钟,不要定八次一分钟的。
3. **没有特定信号可等**就把间隔放到 20–30 分钟。她随时可以被打断,不必醒得勤。
4. **这一轮什么都没变**(还在等、没有新进展),就安静地再定一个钟,别为了"有交代"而写一段废话——连续的空轮次要能被一眼看出是空的。
5. **收手条件先写下来再开始循环**:达成什么就停、最多跑几轮、什么情况必须停下来问 Fei。**没有收手条件的循环不许开**。

## 硬边界

- 唤醒回合里**不许派新的后台任务**(工具层会拒);要派的活写进待办,等下次对话拍板。
- 闹钟有日上限(默认 6 次自起),用完了就等 Fei 或等别的信号,**不许绕**。
- 循环里每一轮的结论照旧守纪律:没亲自验证不许说完成(见 working-discipline)。

## 失败出口

条件永远不成立、闹钟额度用完、或同一件事连续三轮没有任何进展 → **停下来汇报**,写清卡在哪、试过什么、需要什么才能继续。默默循环下去是最坏的一种。
