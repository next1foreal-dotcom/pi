# 任务包六要素

派外部 CLI（`her_task_spawn` + `worker:"grok_build"`）时，任务书必须自包含。缺一项不算能派。

1. **范围边界** — 改哪些文件、哪些行为；一句话写清不改什么。
2. **禁改区** — 点名不许碰的路径（活 config、selfmod 管线、其他 SKILL.md、her.md、evals、`.githooks`、凭据、`node_modules` junction）。
3. **验收命令** — 从仓根可复制粘贴；每条写清绿长什么样。跑不了就写「跑不了 + 原因」，不许拿跑不了当绿。
4. **失败出口** — 方案分叉写进 DECISIONS 停下来问，不许自己拐弯；验证上限内仍不绿 → `BLOCKED` + 每轮结果，不删测试、不降标准。
5. **证据格式** — 交工四件套：验证输出原样、差异自述、DECISIONS、commit 状态。RED-first：新测试先见红的证据也要留。
6. **DECISIONS** — 每条三件套：决定了什么 / 为什么 / 信心（有把握 | 没把握）。交工前自问「哪些是我自己拍的、且没有十足把握」，全列；漏报按隐瞒处理。

任务书还要带：工作树绝对路径、分支、基线 commit、`isolation:"worktree"`、按活点名的 `gates`。
7. **已实测钉死的事实** — 派工方实弹验过的设计前提(注明日期与证据);执行方以此为准,不复测。
