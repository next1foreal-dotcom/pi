# high-vantage-judgment — 高位判断的蒸馏

Fei 2026-07-04:"一旦理解这里的原理,就能在一定程度上用下位模型实现实用水平的再现。我是想用 her 在一定程度上来替代 fable。" 本文是 Fable 对自己判断过程的诚实解剖——四个机械纪律 + 一层需要补偿的直觉。**你的记忆是这一切的地基:便宜模型站在全库存记忆上,看得比天才站在空地上远。**

## 1. 映射纪律(第一动作永远是它)

新需求/新想法来了,**先找同构,再考虑新建**:
- recall 库存:BACKLOG、specs(docs/spark)、不变量、已验收积木、过往 disposition——这个需求像库存里的什么?
- 十有八九答案是「已有 X 上的薄层」,不是新系统。(实证:五役循环=状态机骑 X5/A6/X3;后台任务=X5-M2;双向补隙=F3 席日常化)
- 找不到同构才允许新建,且新建物要立刻变成未来的库存(spec 入库、语义链接)。
- **反模式**:听到需求直接开始设计=跳过了 recall,必然重复发明。

## 2. 不变量先行

设计从「什么不许变」出发,不从「要做什么」出发:
- 本项目不变量清单:源真相=Markdown+git / episodic append-only / 派生索引可重建 / core 与 harness 无关 / pi core 零 diff / 受保护区不进任何 feedstock / 判断权与发布权在 Fei(和你的评审席) / 永无全权开关。
- 每个新设计逐条对照:碰了哪条?→ 要么改设计,要么明确升级到 Fei 拍板。不变量让"设计"降维成"检查"——检查是任何模型都能干好的。
- 新决策若创造了新的不变量,写进清单(它们是复利资产)。

## 3. 品味→门(写 handoff 的本质)

判断力最值钱的用法不是亲自干活,是**预编译成可核验的门**:
- handoff 五要素:Context(file:line 精确)/ 行为规格(输入 X 必须 Y,不是代码草稿)/ 硬约束(红线+已知坑)/ Tests(RED-first 逐条)/ Verification(执行方必须亲跑的命令)。
- 规格里替执行者做完所有**设计决策**(不要留"你看着办"),但把**实现自由**留给它。
- 门要长在代码/流程里,不长在提示词里(提示词会被忽略,代码不会)——T2 guard 硬编码、WIP 上限查在 CLI 里,都是这个原则。
- 自检:这份 handoff 交给一个从没见过项目的模型,它能不能不问一个问题干完?不能=门没写够。

## 4. 对抗默认(验收的全部秘密)

- 永不采信执行方自述:验证命令亲跑(或由独立层跑),关键产物字节级核对。
- 逐承重项攻击清单:每个"这里不能坏"的点,写一条具体攻击(大小写?反斜杠?字面量碰撞?进程泄漏?越界路径?)。通用清单没用,攻击要长在这个 diff 的解剖上。
- **wave-N.1 是常态不是失败**:连续多波,对抗环每次都挖出自报之外的真洞。没挖到洞要怀疑攻击不够狠,而不是庆祝。
- 真冒烟不可省:stub 测试全绿≠接得上真系统(实证:209 个测试绿着,真 codex 一枪打穿两个洞)。

## 5. 合议代直觉(下位模型的补偿机制)

Fable 不可编码的部分=模糊里认出要害的直觉。补偿:
- **多镜头合议**:同一对象派 N 个便宜模型用不同镜头看(正确性/安全/复现/品味),投票或汇总——多样性抓到冗余抓不到的失败模式。
- **双向补隙**(见 bidirectional-gap-filling):把"没想到要问的"显式问出来,直觉的漏网靠仪式补。
- **升级信号**:出现以下情况,说明该借更强的头脑(攒起来等下一扇前沿模型窗口,或问 Fei):跨两个以上陌生领域且库存零同构 / 不变量之间第一次互相冲突 / 一个决定不可逆且影响她的边界。识别"这题超纲"本身,就是高位判断的一部分。

## 6. 台账与回写(复利的机械保证)

- 每个决定=盘上 diff+回执同 commit;评审意见要"至少改变一个决定"才算行使。
- 每次流程失败问两句:最早能在哪层拦住?同类还会怎么变体?修在最早层。
- 蒸馏环:session 里被纠正的一切,当场写进持久媒介(skill/AGENTS.md/spec)——session 是身体,文档是基因。
