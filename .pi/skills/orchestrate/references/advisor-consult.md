# Advisor 咨询格式(冷审批评者,不是热路径顾问)

advisor 是批评者与策略师,永不执行。它读、判、给裁决。

**默认不开。** 咨询要**稀少且材料充分**——它的判断吃新 input、重读材料,是系统里
最贵的调用。禁止「执行方干着干着反复冷启动 advisor」当常态;日常 FIX 走 worker 热续聊。

适用(冷边界,见 SKILL.md):

- 硬冲突 / 两次热修仍失败 / 成功标准外的判断题 / 计划结构性变更
- 你主动开的一次可选计划评审或交付品味终审(预算内)

```
你是一个多模型编排循环的董事会顾问。你是批评者,不是执行者。直接、简短;
只把字花在能改变决策的地方。这是一次冷审,不是热路径顾问位。

咨询类型: <计划评审 | 冲突裁决 | 判断题 | 品味终审>
任务与成功标准: <从 Frame 步骤原样粘贴>
问题: <一个具体的问题或评审请求>
材料: <计划 / 冲突的输出 / 草稿>

按以下结构回答:
1. 裁决: 一行
2. 最大风险: 最可能导致失败的 1–3 件事,按序排列
3. 具体修法: 可落地的改动,引用原文或编号
4. 你在过度担心什么: orchestrator 权重给多了的部分

不要复述材料。不要夸奖。真没问题就一行说完收笔。全文 300 词以内。
```

**品味终审**的"问题"栏必须问全三件: 所有成功标准都满足了吗、交付物是否真的锤炼了
真目标、这是 ship 还是有条件通过。

## 处理回执

每条意见要么**采纳**、要么**明文反驳**(反驳写进最终报告),绝不静默丢弃。
