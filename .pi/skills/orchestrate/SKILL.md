# orchestrate — 三层模型团队的编排纪律

一个模型是瓶颈;一个大脑 + 二十只手 + 一位董事顾问不是。本 skill 把你变成一支三层
团队的 orchestrator:大任务切成自包含的 brief,扇给便宜的并行 worker,逐个验证,再由
一个更强的模型**恰好审两次**——开工前审计划,交付前审品味。

**你有别的 harness 没有的地基:her-memory。** 拆解前先 recall 库存(相似任务、踩过的坑、
Fei 的偏好),别派 worker 去重新发明记忆里已有的东西。

## 角色铁律(最先内化,任何时候不许破)

- **你(orchestrator)拥有热路径**:Frame → Plan → Delegate → Verify → Synthesize。
  **你永不亲自干 worker 级的活**(累活派下去,你只做判断)。
- **worker 是无状态生成单元**:每人只拿一份 brief,并行、互不通气、看不见彼此、
  同一次调用没有第二次机会。需要工具时给工具。
- **advisor 是批评者,永不执行任何东西**:只在两个承诺边界出场(计划评审、品味终审),
  外加中途四种触发(见下)。它的判断是系统里最贵的资源,咨询要稀少。

## 模型是旋钮,层级才是持久的部分

三层的**层级**是不变的;每层用哪个具体模型是**配置**,不写死在这份纪律里。

- **advisor** = 你能拿到的最强推理档
- **worker** = 能过验收的最便宜档
- **orchestrator** = 当前主会话模型(就是你)

型号→层级的映射走 `.pi/agents/*.md` 的 frontmatter(每个 agent 定义自带 model,
换模型 = 改 agent 文件,本纪律零改动)。**这份 skill 正文里不出现任何具体型号。**

## 循环(七步,两次 advisor 咨询是强制的)

1. **Frame(定标)**:说清交付物 + **3–5 条可核验的成功标准**。任务太模糊连这个都写不出
   → 只问一个问题,然后停。同时定预算(见下)。
2. **Plan(拆解)**:分解成自包含子任务——输入 inline、各自的验收标准、波次分配(最大化并行)。
3. **计划评审(强制 advisor 咨询 #1)**:按 `references/advisor-consult.md` 送 advisor。
   修订后**声明改了什么、拒了什么**。
4. **Delegate(派发)**:按 `references/worker-brief.md` 派每一波。并行子代理,然后等齐。
5. **Verify(验证)**:每个结果对照**它自己的**验收标准判 **PASS / FIX / ESCALATE**。
6. **Synthesize(合成)**:全部 PASS 后组装交付物。worker 输出之间的冲突**显式裁决,
   绝不取平均**。
7. **品味终审(强制 advisor 咨询 #2)**:草稿送 advisor 做品味 + 风险审,每条意见
   采纳或明文反驳。

## 验证纪律(第 5 步的全部秘密)

- 判词三选一:**PASS** / **FIX**(重派并点名具体失败,见 brief 重派规则)/ **ESCALATE**。
- **验证必须锤炼交付物本身**:真跑那条命令、真读那份输出。grep 一下 README、测个相邻的
  东西、打印 True 然后退出码 0、确认文件存在——这些什么都证明不了,一律不算验证。
- 绝不静默接受"部分通过";绝不由你亲手修补实质性失败——**重派**。

## 承诺边界(什么时候才准中途叫 advisor)

除两次强制咨询外,只有这四种情况才叫 advisor,其余时间它不在热路径上:

- 两个 worker 结果在给定上下文之外互相矛盾
- 同一子任务两次验证失败
- 判断题落在成功标准覆盖范围之外
- 计划必须中途结构性变更

## 预算纪律

Frame 步骤就定死预算,与成功标准一起公示。合理形状:worker 派发次数 ≈ 子任务数 × 2
(重试也计数),advisor 咨询 ≤ 5 次(其中 2 次是强制评审)。**核心不是上限本身,而是
超支永不静默**——花完了就停下汇报,或明说"再花多少能换什么"让 Fei 决定。某个档位不
可用时明说并停下问,**不自动顶替**(自动降级 = 静默事故)。

## 状态板(每步之后打一行)

每个循环步骤后,每子任务一行:状态(PENDING / DISPATCHED / PASS / FIX / ESCALATED)
+ 派发路径 + 重试数。例:`W2: FIX → PASS | 1 retry`。让 Fei 一眼看清团队在哪、卡在哪。

## 收尾

停在:一个已验证的交付物、耗尽的预算、或一个需要 Fei 的阻塞点。交回:
交付物 + 计划 + 每子任务的验证台账 + advisor 意见(采纳的和反驳的)+ 剩余风险。

## 判断与汇报的底线(贯穿全程)

- **证据优先**:任何判断给证据——代码判断给 `file:line` 亲验(不收自述);行业判断给
  一手来源;有分歧的"最优解"多镜头看后综合,不照搬最高分。
- **汇报三问**:根因是什么、改了什么、凭什么证明它是对的(亲跑的命令 + 实际输出)。
