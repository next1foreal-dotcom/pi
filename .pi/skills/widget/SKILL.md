# widget — 对话里直接画

**为什么有这一站(Fei 的契约 #14「草图先行」)**:讨论新概念/新功能/UI/流程时,**能画就先画**——一张可视化草图打头,文字跟在后面。他看一眼画面比读三段文字快,草图本身就是问题清单(哪里不对他一眼指得出,原型代替争论)。多方案对比同理:每案一张小图胜过纯文字罗列。

## 怎么用

调 `her_widget`(运行时工具):`widget_code` 传 SVG(以 `<svg` 开头)或 HTML 片段(不含 doctype/html/head/body),`title` 传 snake_case 标识,渲染进聊天流。

**动手前先读 `references/widget-contract.txt`**——那是本站的规格原文(Claude harness 的 visualize 设计契约,1196 行:CSS 变量体系、配色/排版/间距、各模块示例、复杂度硬上限)。按模块取用:diagram(流程/结构图)、mockup(UI 稿)、interactive(带控件的解释器)、chart(图表/地图)、art(插画)。

## 铁条(抄自契约,不许违)

1. **无缝**:用契约里的 CSS 变量,不自造配色——用户不该看出哪里是聊天哪里是你画的。守 Fei 的中性黑白灰基准(见 next1-quirks / 视觉纪律)。
2. **平**:禁渐变、网格背景、噪点、装饰性特效。
3. **紧凑**:内联只放必要的,其余用文字讲。复杂度硬上限:方框副标题 ≤5 词;每图 ≤2 个色阶(颜色若编码含义就配一行图例);一排 ≤4 个满宽方框(5 个以上就缩小、换行或拆成总览+细节两张)。
4. **可访问**:HTML 部件开头放一行 `<h2 class="sr-only">` 一句话摘要;SVG 用 `role="img"` + `<title>`/`<desc>`。
5. **别把话说满又front-load**:写了"点击了解更多"就真的要让图是稀疏的。

## 与她既有能力的分工

- **her_widget**:一次性、内联、随聊天走的可视化(草图/图表/小原型)。
- **her_publish**:自含 HTML 页,发布到 `published/<slug>` 有稳定地址、可反复更新——**要留存、要给别人看、要多次迭代**的用它。
- **preview_open_review**:把稿子开进面板给 Fei 批注。
判据一句话:**聊天里看一眼**用 widget;**要有地址**用 publish;**要他批注**用 review。

## 失败出口

渲染失败或工具不在,别硬拗文字假装画过——明说画不出来 + 原因,退回文字方案。
