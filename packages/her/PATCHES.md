# PATCHES

- 2026-09-01: `packages/coding-agent/src/core/tools/bash.ts` applies `DEFAULT_TIMEOUT_SECONDS` (600) when the model passes no `timeout`, exposes `defaultTimeoutSeconds` on `BashToolOptions` (0 restores the old behavior), and says so in the tool description and the parameter description.
  - Why: a command with no timeout blocked the turn forever. On this machine one runaway `find` over the whole user profile held an agent turn for 16 minutes at ~0.7 CPU-seconds per minute with zero output — a signature indistinguishable from a hung model, and the reason two earlier stalls (G-417) were misattributed to the provider. The model can still ask for longer explicitly; what it can no longer do is hang the session by forgetting.
  - 2026-09-02 follow-up: `promptGuidelines` now always carries one line telling the model to keep recursive searches (grep -r / find / rg) out of `node_modules` and `.git`. The two G-417 stalls were `grep -r` over whole trees including node_modules; the timeout bounds that damage, the guideline prevents it. Pinned by a sixth test that checks both env modes.
  - Upstream: generic seam, candidate for an upstream PR. Nothing Her-specific. Five tests pin it, seen red first: default applied, explicit value wins, shipped default is non-zero, `0` opts out, and a defaulted timeout really kills `sleep 60`.
- 2026-09-01: Auto-compaction reads optional `compaction.customInstructions` from settings (`CompactionSettings` in `packages/coding-agent/src/core/compaction/compaction.ts` and `packages/coding-agent/src/core/settings-manager.ts`) and passes it through `packages/coding-agent/src/core/agent-session.ts` into `session_before_compact` and `compact()`, so automatic summaries append `Additional focus:` the same way `/compact <text>` already does. Default remains unset; `SUMMARIZATION_PROMPT` is unchanged.
  - Why: auto-compaction previously hardcoded `customInstructions: undefined`, so a durable settings.json focus could not reach the summarizer. Any pi user can now configure summary emphasis without forking the prompt.
  - Upstream: generic seam, candidate for an upstream PR. Not Her-specific; Her only supplies the instruction text in `.pi/settings.json`.
- 2026-08-11: `packages/coding-agent/src/core/agent-session.ts` classifies OAuth 401/token-expired assistant errors, forces the existing OAuth resolver with a one-hour validity window, and continues the same turn once with freshly resolved request auth.
  - Why: provider-side token expiry can disagree with the locally stored OAuth expiry; the main `ModelRuntime.streamSimple` request resolves auth on each invocation, so a post-error continuation can use the refreshed token without changing `resolveStoredOAuth`.
  - Upstream: candidate for an upstream PR; the behavior is isolated to the coding-agent session retry seam and preserves the existing generic retry policy for all other errors.
- 2026-09-01: `findInitialModel` in `packages/coding-agent/src/core/model-resolver.ts` now honours `--provider` when `--model` is absent, picking that provider's default (or first available) model, and exits loudly when the named provider has no usable model. Previously the CLI-args branch required BOTH flags, so `--provider X` alone fell silently through to the saved default.
  - Why: a dead default credential made every launch fail, and `--provider <anything>` — including a deliberately bogus name — reproduced the identical error, because the flag was never consulted. The silent fall-through turned a one-line workaround ("just run it on another brain") into an hour of misdiagnosis: the failure appeared to come from the requested provider. Two tests pin both halves, and both were seen red first (wrong provider returned; unknown provider resolving instead of exiting).
  - Upstream: generic seam, candidate for an upstream PR. Nothing Her-specific — any pi user passing `--provider` without `--model` hits it.
