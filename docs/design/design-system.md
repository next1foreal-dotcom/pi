### 原则层判例(核心句的展开,源=台账 #5)

- **"细节"的定义比视觉宽**:每个 feature、控件、模式、状态、异常、行为,都是要有人设计、有人理解的细节。限量限的是这个总量,不只是装饰。
- **细节的成本是关系,不是个数**:两个按钮=两个按钮+它们的关系;细节涨,成本二次方涨。到某个数量你就不再是在设计细节,而是在管理细节——"Complexity is a tax on craft."
- **注意力预算不变量**:三个旋钮可以花六个月磨到极好;三十个就成了 enterprise software。三不比三十高贵——是注意力不随旋钮数扩容。
- **复杂度要挣门票**:747 驾驶舱配得上它的复杂,恒温器配不上。复杂不是罪,没挣到门票的复杂才是。
- **隐形决策禁令**(源=台账 #7):模型会"合理地、一致地、不声不响地"替你补上每个未做的决策——页面看着没事,规则正积累成没人选过的架构。决策要么显影记档,要么回退;"请求不是收据",落没落地看发布出来的那一帧。
- **加法有拥护者,删法有敌人**:800 个功能从来不是谁设计出来的,是"一次一个合理请求"长出来的——所以删除必须制度化(门禁/审计/幸存者负全责),不能靠自觉。

### 语言层构成技法(限量之下怎么"成"设计,源=台账 #5)

1. **复杂度集中**:问题真复杂时,别摊在表面——把交互聚进一个主控,把那个主控做到不可思议地好(一千首歌,一个轮子)。
2. **少数控件成为语言**:控件可以换岗,但意义要恒定(OP-1 四个旋钮凭颜色一致成为语汇)。学习被允许——乐器本来要学——但学习来自一致的语言,不来自标签和说明文案(这正是我们"禁解释性文字"的正面证明)。
3. **借已知心智模型**:最好的控件几乎不用解释,因为几乎无从误解(MUJI 拉绳=拉链灯)。想法小,比长得白难得多。
4. **高频动作要有恒定落点**:最常用的那五件,永远有个不动的家,不埋进玻璃后面(VW 认错:"It's a car, not a phone")。选出哪五件,是难的那半。

## 进料协议(每件来料过一遍,不许跳)

1. **真读完**(链接打开、视频看到帧、仓 clone 读源),禁摘要代原文。
2. **提炼原理,丢弃表象**:问"它真正携带的、可迁移的判断是什么"——不是它长什么样。
3. **定落层**:五层挑一;落不进任何层的,先入张力账,不硬塞。
4. **判决**:采(原样/改造)或拒,拒必写为什么——拒的理由和采的一样值钱。改造类判决用**四桶分类**(源=台账 #7 的适配算法):既定可复用模式(≥2 处一致且显然有意)→正式收编;有意的项目分歧→记为分歧并替换基线;一次性实现→**不编码**,顶多列开放问题;基线本就正确→不动。**关键告诫:被适配的项目自身也在受审**——它的某个不一致可能是 bug,把它正式化=把错误封圣;拿不准=问 Owner,不是立规则。
5. **张力显式记账**:与已有原则冲突的,不悄悄覆盖——摆出来,按宪法裁,裁不了留给 Fei。
6. **落成动作**(2026-08-31 Fei「所以?」立):每件采纳的料必须回答**"她的哪个动作因此变了"**——落进她设计时真加载的地方(knowledge/、门检、工具),写明落点。答不出=归档,不算采。本文档是账本,不是运行时;账本上的原理没接线就是收藏夹。
